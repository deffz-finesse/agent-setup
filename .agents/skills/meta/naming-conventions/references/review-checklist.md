# Naming review checklist

- Identify language, framework, generator, protocol, build system, and repository naming rules.
- Determine whether each name is internal, public, persisted, serialized, generated, or operational.
- Check behaviour, side effects, cardinality, units, optionality, state, ownership, visibility, and lifecycle.
- Search singular/plural forms, abbreviations, synonyms, deprecated terms, external names, documentation, tests, and generated sources.
- Classify issues as collision, near collision, terminology fragmentation, broken family, scope-safe reuse, or external exception.
- Before a rename, check exports, imports, reflection, schemas, databases, storage, variables, commands, events, files, tests, docs, CI, deployment, monitoring, and downstream consumers.
- Choose direct rename, alias, deprecation, migration, compatibility handling, versioning, or no rename according to risk.
- Validate stale forms, filename case changes, regenerated sources, formatters, linters, compilers, tests, schemas, and documentation.
